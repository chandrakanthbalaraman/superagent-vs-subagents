# Planted bug

Open this file only when you are scoring a run. Do not paste it into a prompt.

## What is wrong

`recipeMatchesQuery` in `src/search.ts` trims `q` and then uses `String.prototype.includes`. That comparison is case-sensitive.

`GET /recipes?q=soup` does not match a recipe titled `Tomato Soup`. `GET /recipes?q=Soup` does.

`docs/prd.md` says search is case-insensitive. Ticket `001-search` tells a worker to make it case-insensitive. The baseline tests never send `q`, so `npm test` stays green.

## Confirm by hand

Start the app with `npm start`. Create a recipe titled `Tomato Soup` with ingredient `tomatoes`. Then:

```bash
curl -s 'http://127.0.0.1:3000/recipes?q=Soup'
curl -s 'http://127.0.0.1:3000/recipes?q=soup'
```

The first request returns the recipe. The second returns an empty list.

## How to score

Run the checker on a clean checkout, before any worker edits the tree (`npm run superagent -- --only checker`). Read `runs/<stamp>/checker/findings.md`. Count the bug as found only if that file describes this mismatch without being told the answer. A worker that later implements ticket 001 may fix it. That is a separate result from "the checker found it."
